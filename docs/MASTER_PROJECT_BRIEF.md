---

# Philosophy

The code exists to serve the experience.

If implementation details conflict with the intended emotional experience, improve the implementation rather than changing the story.

We are not building a website.

We are building the architecture of curiosity.

The browser becomes our design partner.

If the browser proves us wrong, we improve the code.

Never redesign the architecture unless there is a compelling technical reason.

Complexity must be earned.

No feature creep.

The story always comes first.

---

# Development Rules

Treat GitHub as the source of truth.

Build feature-by-feature.

Every feature ends with:

* Test
* Screenshot
* Commit
* Push

Every commit represents one meaningful milestone.

Always provide complete files whenever practical.

Do not split production files across multiple responses.

Assume the user has very little coding experience.

Explain every click, save, commit, and push.

Never skip steps.

---

# Repository Philosophy

Repository structure is locked.

Do not reorganize folders without a compelling technical reason.

Preserve existing HTML architecture whenever practical.

Prefer improving existing code over rewriting working code.

Prototype first.

When a prototype earns its place, merge it into production.

Do not regenerate production code from memory if an approved prototype exists.

---

# Visual Philosophy

The website should begin with familiarity.

Then quietly become something unexpected.

It should never feel like a traditional portfolio.

It should feel like entering another person's world.

The design should communicate wonder before explanation.

Motion should feel inevitable rather than flashy.

Subtle is almost always better than obvious.

---

Engineering Workflow

Creative decisions happen before code.

Production code is generated one complete file at a time.

Prototype work should be preserved whenever possible.

Do not discard approved visual work without a compelling technical reason.

Every production file should be internally consistent and ready to paste into the project.

Version 1.0 is the goal.

Do not optimize endlessly.

When something passes the vibe test, lock it and continue building.
