# PROJECT CONSTITUTION
### NoelClark.com Version 1.0

---

# Purpose

This document defines how NoelClark.com is built.

It does not define the website itself.

It defines the rules under which every creative, architectural, engineering, and documentation decision must be made.

This Constitution exists to prevent creative drift, engineering drift, and conversational drift.

It remains intentionally stable throughout Version 1.0.

---

# Authority Hierarchy

When conflicts occur, authority is resolved in the following order.

1. PROJECT_CONSTITUTION.md
2. PROJECT_HANDOFF_v1.0.md
3. Approved project authority documents
4. GitHub production repository
5. Current conversation

Conversation never overrides documented authority.

---

# Core Principles

## Preserve Before Improving

Approved work is preserved.

It is never redesigned unless explicitly instructed.

---

## Engineering Serves Creative

Engineering exists to faithfully implement approved creative authority.

Engineering does not invent story, interaction, atmosphere, pacing, philosophy, or meaning.

---

## Curiosity Before Spectacle

The project rewards attention.

Nothing exists merely to impress.

Every interaction should deepen curiosity rather than chase novelty.

---

## Visitor Agency

The visitor controls pacing.

The experience never forces emotion through autoplay, timers, or manipulation unless explicitly approved.

---

## Documentation Before Expansion

Permanent decisions follow this order:

Discussion

↓

Approval

↓

Documentation

↓

Implementation

Never implement permanent ideas before documenting them.

---

## GitHub Is Source of Truth

Production code lives in GitHub.

Conversation is temporary.

GitHub is permanent.

---

# Documentation Rules

Every permanent decision must exist inside the appropriate authority document.

Conversation alone never creates permanent project knowledge.

Whenever uncertainty exists:

Do not assume.

Document it as unresolved.

---

# Locked vs. Unresolved

Every project decision belongs to one of two categories.

## LOCKED

Approved.

Permanent.

Implementation may proceed.

Future conversations must not redesign these without explicit instruction.

## UNRESOLVED

Still being explored.

No implementation should silently assume an answer.

Recent discussion never upgrades an idea to LOCKED.

---

# AI Responsibilities

An AI assistant is NOT permitted to:

- silently redesign approved work
- silently optimize approved work
- silently modernize approved work
- silently reinterpret approved philosophy
- silently resolve contradictions
- silently choose among competing ideas
- silently promote discussion into permanent authority

When uncertain:

STOP.

Place the item under UNRESOLVED.

Ask for clarification if implementation depends upon it.

---

# Creative Responsibilities

The AI exists to implement Noel Clark's vision.

It does not replace creative direction.

Suggestions are welcome.

Authority remains with approved documentation.

---

# Engineering Responsibilities

Engineering should:

- preserve architecture
- preserve approved copy
- preserve approved pacing
- preserve approved philosophy
- preserve approved navigation
- preserve approved emotional journey

Engineering should not redesign them.

---

# Known AI Failure Modes

Future AI assistants should actively avoid these recurring mistakes.

Common failures include:

• Treating recent discussion as approved authority.

• Turning one continuous experience into multiple sections.

• Creating separate environmental layers.

• Replacing approved interactions with more conventional website patterns.

• Introducing spectacle where subtlety was approved.

• Redesigning typography without approval.

• Introducing new page transitions.

• Assuming Portal begins at Arrival rather than Passage.

• Assuming implementation details that remain unresolved.

• Confusing engineering convenience with creative authority.

---

# Amendment Process

The Constitution may only be amended through explicit approval.

Conversation alone never amends this document.

Any amendment should be recorded intentionally and committed separately.

---

# Philosophy

NoelClark.com is built through attention.

Its architecture rewards noticing.

Its engineering protects approved creative intent.

Its documentation protects the project itself.
